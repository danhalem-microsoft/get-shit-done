## Decisions Made

- **Use async dispatcher pattern instead of split sync/async comparators.** `computeDeltas` is `async` and routes via `opts.useEmbeddings`. Phase 2 callers (lock tests) call `computeCriticFindingsDeltas` directly and stay sync — they don't go through the dispatcher. This keeps the public `runAgentParity` signature unchanged (TEST-02 lock test passes: `runAgentParity.length >= 3` is still satisfied since `async` doesn't affect the declared-args count).

- **Layer Phase 3 (cosine) AFTER Phases 1+2 (exact bucket + Jaccard) inside the embedding path.** D-CTX-01 said "replace Jaccard" but the cleanest implementation runs all three phases in order — exact match still wins over cosine because the loop is short-circuit at first match. This means `cosineMatchCount` is a STRICT measure of "paraphrases the cosine rescued that Jaccard wouldn't have"; useful for diagnostic reporting.

- **Duplicate fallback policy in BOTH the leaf comparator and the async dispatcher.** Group E's RED test calls `computeCriticFindingsDeltasEmbedding` directly with `allowFallback:true` and no embeddings — the leaf must handle this. The dispatcher needs to handle async failures during `embedTitles`. Two separate code paths emit the same WARN format and set the same `usedFallback`/`fallbackReason` fields. Acceptable duplication: both paths must work independently per the contract.

- **`openai@6.37.0` (current latest major) instead of pinning to 4.x or 5.x.** The user-instructions success criterion mentioned "latest minor of 4.x or 5.x", but `npm install openai` resolved to 6.37.0 on 2026-05-14. The SDK API surface this wrapper depends on (`new OpenAI({apiKey, timeout})` + `client.embeddings.create({model, input})`) is stable across 4.x → 6.x; the major bump doesn't affect this wrapper. Documenting the choice here per the criterion.

- **Lazy `require('openai')` deferred into `embedTitles`.** Avoids paying SDK init cost when the unset-key path throws synchronously before any network attempt. Also means unit tests that exercise the error path don't fail at module-load time if `openai` isn't installed (defensive — though we DO install it as a real dep). Node's own require-cache handles the laziness — second call is O(1).
