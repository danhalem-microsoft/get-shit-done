## Phase Boundary

Phase 2 shipped a correct critic-comparator MECHANISM (severity normalization + fuzzy title matching, locked by 16 unit tests in `tests/critic-comparator-fix.test.cjs`). Live N=5 parity revealed the comparator now does meaningful work on real data (12 baseline findings vs 11 candidate findings on `critic-code`, for example — vs. the pre-fix trivial-pass behavior of `0 vs 0 → overlap 1.0`). But the live overlap is ~0.33 against a 0.85 threshold, and the diagnosis is that **lexical Jaccard is structurally limited** as a proxy for LLM semantic equivalence: synonyms like "no input validation" ↔ "missing input validation" preserve meaning while destroying Jaccard score.

Phase 2.1 closes this gap by REPLACING lexical similarity with embedding-based cosine similarity. The user explicitly chose this path over four alternatives (recalibrating the threshold, severity-stratified thresholds, H8-empirical thresholds, defer-to-Phase-7) on 2026-05-14.

<decisions>
## Implementation Decisions

### Comparator architecture
- **Replace Jaccard-title-bag with cosine-similarity over embedding vectors.** The Phase 2 `titleWordBag` + `jaccardSimilarity` helpers stay in the file as the fallback path (see Fallback below).
- **Primary embedding model:** `text-embedding-3-small` (OpenAI) — 1536-dim, ~$0.02 per million tokens, well-characterized for short-text semantic similarity. Implementation must NOT hardcode the model name as a string literal — load from `workflow.embedding_model` config (default `text-embedding-3-small`) so the model can be swapped without code change.
- **Threshold:** Start at **0.80 cosine** for "same finding". Document the threshold-vs-Jaccard relationship in code comments (cosine 0.80 ≈ Jaccard 0.50 for the same meaning, empirically). If the H8 variance run shows the same-critic-twice baseline produces cosines well above 0.80 (high signal), this threshold is correct. If H8 shows borderline cases, document for future tuning. Threshold is NOT gated on H8 — H8 is informational, not blocking.
- **API endpoint:** Use the OpenAI Python/Node SDK with `OPENAI_API_KEY` from env. The user already has Copilot/OpenAI access; verify `process.env.OPENAI_API_KEY` is set before invoking. If absent, error early with a clear message about which env var is needed and how to obtain a key.

### Fallback path
- **When embedding API is unreachable or `OPENAI_API_KEY` is unset:** comparator falls back to existing Jaccard implementation (Phase 2's `titleWordBag` + `jaccardSimilarity` chain) with a **logged warning** on stderr: `WARN: embedding API unavailable; falling back to Jaccard (Phase 2 contract — lexical similarity only)`. The fallback must NOT silently change the test outcome — it must surface explicitly that the result is lexical-only.
- **Fallback test:** at least one test invocation simulates a missing API key (e.g., by unsetting `OPENAI_API_KEY` in the env) and asserts the warning appears in stderr AND the comparator returns the same shape as in primary mode.

### H8 variance estimate (informational)
- **Run each critic 3x against its own baseline.** Output: `integration/test-fixtures/baselines/variance/critic-{lens}-N3.json` with `{ jaccard: [], cosine: [] }` arrays of pairwise comparisons (3 pairs per critic).
- **Why informational, not gating:** the embedding cosine threshold is the actual phase-exit contract. H8 documents the per-critic noise floor so future threshold debates have evidence. If H8 reveals embedding cosine variance > 0.20 within-critic, that's a real finding (the embeddings aren't as discriminating as expected) — surface in SUMMARY.md but do NOT block the phase.
- **Cost:** ~$5 for the 18 critic runs (6 critics × 3) plus embedding cost (negligible vs critic invocation cost). Inside the $20 phase cap.

### Test changes
- **`tests/critic-comparator-fix.test.cjs` STAYS** — locks Phase 2 mechanism. Add new sub-tests for the embedding fallback path.
- **`integration/critic-parity.test.cjs` UPDATES** — uses the new comparator. Threshold stays 0.85 (now interpreted via cosine). Document the interpretation in test comments. If a critic falls below 0.85, the test fails with per-finding diagnosis (which baseline findings have no semantic match) — NOT silent skip.
- **New test:** `tests/critic-comparator-embedding-shape.test.cjs` — locks the embedding-path JSON contract, fallback behavior, threshold constant, model name from config.

### Reviewing
- After implementation, run `/gsd-peer-review 2.1` to get cross-AI review of the design. Optional but recommended given this is the load-bearing fix for the Phase 2 contract.

### Claude's Discretion
- Module decomposition within `agent-parity.cjs` vs. a new helper file (`agent-parity-embedding.cjs`). Planner picks based on existing module size.
- Caching strategy for embeddings (per-baseline embedding cache vs. re-embed every run). Recommend per-baseline cache at `integration/test-fixtures/baselines/embeddings/<critic>/<finding-sha>.json` — embedding is deterministic for a given input + model, so cache lookup is safe.
- Per-test parallelism: existing tests use `node --test` with `--test-concurrency`. New tests should remain concurrency-safe (no shared state mutation).
</decisions>

<specifics>
## Specific Ideas

- **Embedding cache key:** `sha256(model_name + ':' + title_normalized)` — guarantees cache invalidation when the model changes. Normalize title: lowercase, collapse whitespace, strip leading severity markers like `[CRITICAL]`.
- **Batch embedding requests:** the OpenAI API supports up to 2048 input strings per request. Each parity run has ~50–100 findings to compare; batch them in one request per critic for cost + latency efficiency.
- **Per-finding diagnosis on failure:** when a critic's overlap drops below 0.85, the test should produce a structured diff listing each baseline finding with its best-match candidate (and the cosine score), so the reviewer can see WHY parity dropped — is it that the candidate produced different findings, or that the same findings were rephrased past the threshold?
- **H8 baseline location:** `integration/test-fixtures/baselines/variance/critic-{lens}-N3.json` — keeps variance baselines OUT of the main `baselines/critic-{lens}/` dir (which is the parity-comparison source), so the variance set is unambiguous about its role.
</specifics>

<deferred>
## Deferred Ideas

- LLM-judge comparator (Path 3 from 02-07-SUMMARY-fixes.md). Ask another LLM "are these two findings describing the same issue?". Most accurate but most expensive (~$3–5 per parity run). Reconsider if Phase 2.1 embeddings don't clear 5/6 critics at 0.85.
- N=3-5 baseline re-capture (Path 4). Capture baselines as plausible-finding distributions instead of single samples. Defers to Phase 7+ if embeddings prove insufficient.
- Per-severity threshold stratification (Path 1 from 02-07-SUMMARY-fixes.md). If embedding cosine produces clear bimodal distribution between critical and warning/info severities, revisit and stratify thresholds. Defer unless H8 variance shows it's needed.
- Migrating other tests (e.g., shape-based parity tests) to use semantic comparison. Phase 2.1 changes ONE comparator path; broader migration is its own decision.
</deferred>
