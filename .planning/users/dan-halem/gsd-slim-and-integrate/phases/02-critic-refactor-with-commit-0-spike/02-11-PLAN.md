Phase 2 exit-gate gap closure #3 (per Wave 6 status check) + research-directed env-propagation fix. Two layered issues:

1. **Bazel sandbox cannot find files the Phase 2 static tests read.** The Phase 2 list-comprehension `data = ["//integration/helpers:test_helpers"]` is insufficient — tests read agent files, `bin/install.js`, workflow files, SDK sources, and the walltime ledger. Result: 6 of 7 static tests `FAIL` with ENOENT under `bazel test --test_tag_filters=phase-2-critic,-requires-api-key`, even though all 30 sub-tests pass under `node --test`.

2. **Live tests can't see Azure env vars** even when developer sources `~/.env` — the existing `.bazelrc` only forwards `ANTHROPIC_API_KEY`, not the `AZURE_OPENAI_*` set the embedding-cosine parity comparator needs. Per the bazel docs `try-import %workspace%/user.bazelrc` is the canonical escape hatch.

Single-plan fix: extend `//:project_sources` to include `bin/**`; broaden Phase 2 list-comp `data`; add Azure `--test_env` lines + `try-import` to `.bazelrc`; gitignore `user.bazelrc`. After this plan, the static-only suite runs GREEN in bazel from any shell.
</objective>

`.bazelrc` env research (per Wave 6 status check + WebSearch of bazel docs):
- Canonical: `--test_env=VARNAME` (no value) inherits from shell. Developer runs `set -a; source ~/.env; set +a` then `bazel test`.
