**Placeholder substitution mechanism (CRITICAL CLARIFICATION):**

Template placeholders `{planning_root}`, `{phase_dir}`, `{state_path}` are filled by the **workflow code at template expansion time**, NOT by the agent. The substitution flow is:

1. Workflow calls `gsd-tools.cjs init <command>` → gets `planning_root` from JSON output
2. Workflow calls `gsd-tools.cjs template fill <template>` or reads template content directly
3. Template content containing `{planning_root}` is replaced via one of:
   - `cmdTemplateFill` internal variable replacement (if template.cjs supports it)
   - Workflow-level `sed` or string substitution in the bash script
   - The workflow writes the expanded content to the target file
4. The resulting document contains fully-resolved paths like `.planning/users/dan/frontend/STATE.md`

For templates that are part of spawn prompts (agent invocation), the **orchestrator workflow** does the substitution before passing the prompt to the agent. Agents never see `{planning_root}` — they see the resolved path.
