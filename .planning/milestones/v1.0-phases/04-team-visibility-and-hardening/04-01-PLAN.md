    2. In `loadConfig()`, add an env var override pass AFTER ALL normalization blocks (parallelization normalization, model_overrides merge). The sequence must be:
       1. Merge defaults → global config → per-project config (existing merge loop, ~line 188)
       2. Run all normalization blocks (parallelization boolean/object normalization, model_overrides merge) — these fix up values from config files
       3. Apply env var overrides LAST (highest priority, already self-parsed to correct types)

       Place this block AFTER the `result._sources = sources;` line (just before `return result;`):
       ```javascript
       // Layer 3: Environment variable overrides (highest priority)
       // Applied AFTER normalization so env vars always win and don't get re-normalized.
       // Env var values are self-parsed here (string→boolean/number), so normalization
       // blocks above only need to handle config-file values.
       for (const [key, envName] of Object.entries(ENV_KEY_MAP)) {
         const envVal = process.env[envName];
         if (envVal !== undefined) {
           // Parse booleans and numbers from string env values
           if (envVal === 'true') result[key] = true;
           else if (envVal === 'false') result[key] = false;
           else if (/^\d+$/.test(envVal)) result[key] = parseInt(envVal, 10);
           else result[key] = envVal;
           sources[key] = `env:${envName}`;
         }
       }
       result._sources = sources;  // Re-assign after env var pass
       ```
       **CRITICAL:** The env var loop MUST go AFTER the parallelization normalization block and model_overrides merge — NOT before them. This ensures:
       - Config file values (which may be strings like `"false"`) get normalized by the existing blocks
       - Env var values override the already-normalized result with their own self-parsed types
       - `GSD_PARALLELIZATION=false` correctly resolves as boolean `false` regardless of what config files contain

    3. Export `ENV_KEY_MAP` from `core.cjs` module.exports so `cmdConfigResolve` can reference it.

    4. Create `cmdConfigResolve(cwd, key, raw)` function in `core.cjs` (after loadConfig):
       - Call `loadConfig(cwd)` to get full config with `_sources`
       - If `key` is not in the config defaults/keyMap, `error('Unknown config key: ' + key)`

         - `global`: read `.planning/config.json` directly for that key (or null)
         - `project`: read per-project config.json for that key (or null)
         - `env`: check `ENV_KEY_MAP[key]` and `process.env[envName]` (or null)
       - `output({ key, value: config[key], source: config._sources[key], layers }, raw)`

    5. Add `cmdConfigResolve` to `module.exports`.
