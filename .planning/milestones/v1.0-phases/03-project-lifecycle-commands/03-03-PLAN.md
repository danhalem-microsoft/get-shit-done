  <action>
    Rewrite `get-shit-done/workflows/new-project.md` to implement the two-step bootstrap pattern from CONTEXT.md decisions:

    **Step 0: Pre-init bootstrap**
    ```bash
    SETUP=$(node "$HOME/.claude/get-shit-done/bin/gsd-tools.cjs" init project-setup)
    if [[ "$SETUP" == @file:* ]]; then SETUP=$(cat "${SETUP#@file:}"); fi
    ```
    Parse: `user`, `projects`, `global_config`, `planning_exists`

    **Step 1: Show existing projects + ask for name**
    - If `projects` array is non-empty: display existing projects with status summary (name, phase, progress). Ask: "You have N projects. Create a new one?"
    - Ask: "What should this project be called?" — this is the FIRST question
    - Take the human name, slugify with `generateSlugInternal()` (via `gsd-tools.cjs generate-slug "user input"`)
    - Show slug: "Project will be created as: my-auth-service. Proceed?"
    - Check duplicate: if slug exists in projects array, error: "Project my-auth-service already exists. Use /gsd:switch my-auth-service to work on it."

    **Step 2: Ask scope**
    - "Which monorepo subdirectory or Bazel target is this project scoped to? (press Enter to skip)"
    - Store response for config.json

    **Step 3: Create directory structure + set active**
    ```bash
    mkdir -p ".planning/users/${USER_SLUG}/${PROJECT_SLUG}"
    ```
    - Copy global config to project config (seed): `cp .planning/config.json .planning/users/${USER_SLUG}/${PROJECT_SLUG}/config.json` (if global exists)
    - If scope was provided, add `scope_path` to the project config.json
    - Set active context:
    ```bash
    node "$HOME/.claude/get-shit-done/bin/gsd-tools.cjs" switch "${PROJECT_SLUG}"
    ```

    **Step 4: Normal init (now has active project)**
    ```bash
    INIT=$(node "$HOME/.claude/get-shit-done/bin/gsd-tools.cjs" init new-project)
    if [[ "$INIT" == @file:* ]]; then INIT=$(cat "${INIT#@file:}"); fi
    ```
    Continue with existing flow: questioning, research, requirements, roadmap.

    **Also update `commands/gsd/new-project.md`:**
    - Ensure the command file still references the workflow correctly
    - Update description to mention multi-user project creation
    - Keep existing allowed-tools

    The key behavioral change: the workflow now asks for project NAME before doing any questioning about the project itself. The pre-init step works without an active project.
